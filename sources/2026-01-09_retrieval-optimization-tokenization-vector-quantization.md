## 第1课：课程介绍

### 核心概念
- **RAG（检索增强生成）** 包含两个主要步骤：检索（Retrieval）和生成（Generation）
- 本课程聚焦于优化第一步——检索步骤
- 涵盖内容：分词机制、搜索质量度量、HNSW 优化、向量量化

### 关键知识点
- 分词器（Tokenizer）将文本转换为数值 ID 序列，对应词或子词
- HNSW（层次化可导航小世界图）是向量数据库中最常用的近似搜索结构
- 量化技术可将内存使用降低最多 **64倍**

> **生动比喻**：HNSW 搜索就像邮递包裹——顶层先找到目标所在的"省"，下一层找到"城市"，越往下越精确，直到找到确切地址。

## 第2课：嵌入模型（Embedding Models）

### 核心概念
- 嵌入模型将任意文本转换为**固定维度的向量**，用于计算文档间的相似度
- 模型不直接操作文本，需要分词器作为"翻译层"
- Transformer 架构：嵌入模型通常是 **encoder-only** 变体

### 文本转向量的完整流程
1. **分词**：文本被分词器切割为 token 序列
2. **Token ID 映射**：每个 token 对应一个数值 ID
3. **输入嵌入查找**：通过查找表将 ID 映射为向量（上下文无关）
4. **位置编码**：添加位置信息，使模型感知 token 顺序
5. **多层 Transformer 处理**：注意力机制捕获 token 间关系
6. **池化（Pooling）**：将所有 token 向量平均为单一文本向量
7. **归一化（Normalization）**：输出最终嵌入向量

### 重要特性
- **输入 token 嵌入是上下文无关的**——同一个 token 无论出现在什么语境中，初始嵌入相同
- **输出 token 嵌入是上下文相关的**——经过注意力层后，同一 token 在不同句子中产生不同向量
- 模型有最大 token 数限制（如 256），超出部分会被截断

> **生动比喻**：输入嵌入就像字典中每个词的基础含义，而输出嵌入则像这个词在具体句子中的"活用含义"——"苹果"在科技文章和水果店里意思完全不同。

## 第3课：分词器的角色

### 三大分词算法

| 算法 | 核心思想 | 特点 | 使用者 |
|------|---------|------|--------|
| **BPE（字节对编码）** | 自底向上，迭代合并最常见的相邻 token 对 | 按空格预分割，不跨越词边界 | OpenAI (GPT系列) |
| **WordPiece** | 类似 BPE，但区分词首和词中字母（##前缀） | 基于分数选择合并对，学习词根和词缀 | BERT、Sentence Transformers |
| **Unigram** | 自顶向下，从大词表开始逐步删除 | 基于损失函数移除影响最小的 token | Cohere 多语言模型 |

### BPE 详细流程
1. 按空格分割文本
2. 初始化词表为所有单字符
3. 迭代：找到最频繁的相邻 token 对 -> 合并为新 token -> 加入词表
4. 重复直到达到目标词表大小

### WordPiece 特殊之处
- 用 `##` 前缀标记词中间的字母（如 "walking" -> "walk" + "##ing"）
- 目标：让模型理解 walk/walking/walked 共享"行走"的语义

### Unigram 独特之处
- 从大词表开始，逐步删除对整体损失影响最小的 token
- 可避免"幽灵 token"问题（从不被使用但占位的 token）

### SentencePiece
- 不是新算法，而是 BPE/Unigram 的特殊实现
- **不以空格为分割边界**，将空格视为普通字符
- 适合无空格语言（如中文、日文）和代码（Python 缩进有语义）

> **生动比喻**：BPE 像是拼乐高——从单块开始不断组合热门搭配；Unigram 像是雕刻大理石——从整块开始逐步削去不重要的部分。

## 第4课：分词的实际影响

### 常见问题场景

| 问题类型 | 表现 | 解决思路 |
|---------|------|---------|
| **Emoji** | 被转换为未知 token [UNK]，不同 emoji 无法区分 | 选择支持 Unicode 的模型或用文字替代 |
| **拼写错误** | 产生完全不同的 token 序列，相似度大幅下降 | 输入预处理/拼写纠正 |
| **数值/价格** | $55 和 $559 可能因 token 重叠而相似度高 | 使用元数据过滤（payload filter） |
| **日期格式** | 同一日期不同格式产生极低相似度 | 日期标准化 |
| **专业术语** | 被切成大量无意义子词 | 考虑领域适配模型 |

### 关键发现
- **语义搜索不是万能的**——对数值比较、格式差异、特殊字符处理能力有限
- OpenAI 嵌入模型（100k+ 词表）在 emoji、拼写错误方面表现优于小模型
- **最佳实践**：对数值约束使用向量数据库的 **payload 过滤器**

### Qdrant 实战示例
```
# 语义搜索 + 价格过滤
query: "适合冬天穿的衣服，40美元以下"
-> 语义搜索找到"冬天相关"的结果
-> payload filter 确保 price <= 40
```

> **生动比喻**：语义搜索像是一个理解自然语言的图书管理员，但他分不清数字大小——你说"找便宜的书"他能理解，但"100元以下"需要另一个系统来精确筛选。

## 第5课：搜索相关性度量

### 度量体系

**一、相关性指标（Relevancy-based）**
- **Precision@K**：前 K 个结果中相关文档的比例
- **Recall@K**：所有相关文档中被返回在前 K 个的比例

**二、排序指标（Ranking-based）**
- **MRR（Mean Reciprocal Rank）**：第一个相关结果的位置的倒数的平均值
  - 关注"能否把最相关的放在第一位"

**三、分数指标（Score-based）**
- **DCG（Discounted Cumulative Gain）**：考虑位置折扣的累积增益
- **NDCG（Normalized DCG）**：DCG / IDCG，归一化到 [0, 1]

### 实战流程
1. 构建 Ground Truth 数据集（查询 -> 最佳匹配文档）
2. 使用 **ranx** 库计算指标
3. 对比不同方案（如：搜索产品名 vs 搜索产品描述）

### 关键发现
- 在 WANDS 数据集上，搜索**产品名**比搜索**产品描述**效果更好
- 测量检索质量比测试完整 RAG 管道简单得多（后者需要 LLM-as-judge）

> **生动比喻**：Precision 像"你给我的10本书里有几本是我想要的"；Recall 像"我想要的所有书中你给了我几本"；MRR 像"我翻了几页才找到第一本有用的"。

## 第6课：优化 HNSW 搜索

### HNSW 核心机制
- **多层图结构**：顶层最稀疏（少量节点），底层最密集（所有节点）
- 搜索从顶层开始，逐层向下，逐步缩小搜索范围
- 每一层中只检查前一步选中的点及其直接邻居

### 两个关键参数

| 参数 | 含义 | 增大的效果 | 代价 |
|------|------|-----------|------|
| **M** | 每个节点的边数 | 提高近似质量 | 增加内存和索引时间 |
| **ef** | 每层选取的候选点数 | 提高搜索精度 | 降低搜索速度 |

### 实验结果
- 默认配置（M=16, ef=100）：Precision@25 约 0.998
- 增大参数后精度进一步提升，但也有速度和内存代价
- **HNSW 只能改善近似质量，不能修复嵌入模型本身的缺陷**

### 分段实现
- 实际数据库中 HNSW 不是全局单一图，而是分成**不重叠的段（segments）**
- 好处：可分布式部署、并发处理、单段重建

> **生动比喻**：HNSW 参数调优就像调望远镜——M 像镜片直径（越大越清晰但越重），ef 像对焦精度（越高越准但越慢）。搜索结果只能与你的"望远镜品质"（嵌入模型）一样好。

## 第7课：向量量化

### 三种量化技术对比

| 方法 | 压缩率 | 原理 | 精度影响 | 速度提升 |
|------|--------|------|---------|---------|
| **乘积量化 (PQ)** | 可达 64x | 将向量分段，每段用聚类中心 ID 替代 | 较大 | 中等 |
| **标量量化 (SQ)** | 4x | 将 float32 转为 int8 | 较小 | 明显 |
| **二值量化 (BQ)** | 32x | 将每个维度转为 0/1 | 最大 | 最快（40x） |

### 乘积量化 (Product Quantization) 详解
1. 将向量切分为子向量
2. 对每组子向量进行 K-means 聚类（K=256，刚好 1 字节）
3. 用聚类中心 ID 替代原始子向量
4. 命名来源：利用子空间的**笛卡尔积**

### 标量量化 (Scalar Quantization) 详解
- 将 float32 映射到 [0, 255] 的整数范围
- 4 字节 -> 1 字节，固定 4 倍压缩
- **通常是首选方案**——精度损失小，速度提升明显

### 二值量化 (Binary Quantization) 详解
- 正数 -> 1，负数/零 -> 0
- 32 bit -> 1 bit
- 需要 **oversampling**（多取候选）+ **rescoring**（用原始向量重算距离）

### Rescoring（重评分）机制
- 量化后很多不同向量有相同表示 -> 无法区分
- 保留原始向量在磁盘上
- 先用量化向量粗筛，再用原始向量精排

### 实验结论
- 标量量化（无论是否 rescore）精度最高
- 二值量化 + rescoring 效果也不错
- 乘积量化在高压缩率下精度下降明显

> **生动比喻**：量化就像地图的不同比例——标量量化是 1:10000 的城市地图（细节足够）；乘积量化是 1:100000 的省级地图（大方向对但细节丢失）；二值量化是只标"东南西北"的草图（极度简化但极快）。

## 总结表

| 课程主题 | 关键技术 | 实用建议 |
|---------|---------|---------|
