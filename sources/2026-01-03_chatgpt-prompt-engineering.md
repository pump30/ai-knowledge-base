# ChatGPT Prompt Engineering for Developers 学习笔记

> 课程来源：DeepLearning.AI  
> 讲师：Andrew Ng & Isa Fulford (OpenAI)

---

## 第1课：Introduction（引言）

### 核心概念
- **Base LLM（基础大语言模型）**：基于文本训练数据预测下一个词。问"法国的首都是什么？"可能会续写更多问题，而非直接回答。
- **Instruction-tuned LLM（指令微调模型）**：经过指令微调和RLHF训练，能够按照指令完成任务。

### 生动比喻
> 基础LLM就像一个**博览群书但不听指挥的学者**——你问它问题，它可能会继续列出更多问题而非回答你。而指令微调LLM则像一个**听话的聪明助手**——你说什么它做什么。

### 关键要点
- 本课程聚焦于开发者如何通过API调用LLM快速构建应用
- 使用指令微调LLM时，想象你在给一个聪明但不了解你任务细节的人下达指令
- 两大提示词原则预告：清晰具体 + 给模型思考时间

---

## 第2课：Guidelines（提示词准则）

### 原则一：编写清晰、具体的指令

**策略1：使用分隔符**
- 三重反引号 ` ``` `、引号、XML标签、章节标题等
- 防止提示词注入攻击（Prompt Injection）

**策略2：要求结构化输出**
- 要求JSON、HTML等格式输出，便于程序解析

**策略3：让模型检查条件是否满足**
- 如果输入不满足前提条件，让模型停止并说明

**策略4：Few-shot Prompting（少样本提示）**
- 给出成功示例，让模型模仿风格完成任务

### 原则二：给模型思考时间

**策略1：指定完成任务所需的步骤**
- 将复杂任务拆解为步骤1、步骤2...

**策略2：让模型先自行计算再下结论**
- 例如：先自己解题，再比较学生答案是否正确

### 模型局限：幻觉（Hallucination）
- 模型会编造看似合理但不真实的内容
- 减少幻觉的方法：让模型先找到相关引用，再基于引用回答

### 生动比喻
> "清晰"不等于"简短"。就像给厨师下菜单——你说"做个好吃的"不如说"做一份三分熟的牛排配黑椒汁"。**越具体的指令，越能得到你想要的结果。**
>
> 给模型思考时间就像**考试时给学生草稿纸**——不给草稿纸直接写答案，出错概率大增。

## 第3课：Iterative Prompt Development（迭代提示词开发）

### 核心思想
- 没有人能一次写出完美的提示词，重要的是**迭代改进的过程**
- 类似机器学习的开发循环：想法 -> 实现 -> 实验结果 -> 分析 -> 改进

### 迭代流程
1. 写出初始提示词（清晰具体 + 给模型思考时间）
2. 运行查看结果
3. 分析不满意的原因（太长？方向偏？缺细节？）
4. 修改提示词，重新运行
5. 重复直到满意

### 实战案例：椅子产品描述
- 第一版：输出太长 -> 加入"不超过50词"限制
- 第二版：面向消费者 -> 改为面向零售商，强调技术细节和材料
- 第三版：缺少产品ID -> 加入"包含所有7字符产品ID"
- 第四版：需要表格 -> 加入"输出HTML格式表格"

### 生动比喻
> 迭代提示词就像**雕刻一座塑像**——你不会期望第一刀就完美，而是先勾出大形，再一刀一刀精雕细琢。

## 第4课：Summarizing（文本摘要）

### 核心能力
- 利用LLM快速总结大量文本（产品评论、文章等）
- 可以控制摘要长度（字数/句数/字符数）

### 高级技巧
- **针对特定部门的摘要**：加入"聚焦于配送相关内容"或"聚焦于价格相关内容"
- **提取 vs 摘要**：用"extract"替代"summarize"，获取更精确的特定信息
- **批量摘要**：循环处理多条评论，生成仪表板

### 生动比喻
> LLM摘要就像一个**超快的秘书**——你扔给他100页报告，他能在几秒内告诉你每一页的核心要点，而且还能根据你是CEO还是物流经理，调整汇报重点。

---

## 第5课：Inferring（推断）

### 核心能力
- **情感分析**：判断正面/负面情绪
- **情绪提取**：列出文本中表达的具体情绪
- **信息提取**：提取产品名、品牌、特征等
- **主题推断**：从文本中提取讨论的话题
- **零样本分类**：判断文本是否涉及特定主题

### 与传统ML的对比
- 传统方法：收集数据 -> 训练模型 -> 部署 -> 推理（每个任务都要重来）
- LLM方法：写一个提示词 -> 直接获得结果（一个模型搞定所有任务）

### 组合技巧
- 用一个提示词同时提取多个字段（情感 + 是否愤怒 + 商品名 + 品牌）
- 输出为JSON格式便于后续处理

### 生动比喻
> 传统NLP就像**为每道菜专门买一个锅**，而LLM就像一口**万能锅**——煎炸蒸煮炖全能，只需换个调料（提示词）。

---

## 第6课：Transforming（文本转换）

### 核心能力

**翻译**
- 支持数百种语言的翻译
- 语言识别
- 多语言同时翻译
- 正式/非正式语体切换
- 通用翻译器（处理多语言客服消息）

**语气转换**
- 俚语 -> 商务信函
- 非正式 -> 正式

**格式转换**
- JSON -> HTML
- Python字典 -> HTML表格
- 各种数据格式互转

**拼写和语法纠错**
- 校对和修正语法错误
- 支持使用redlines库查看修改diff
- 可以同时改写风格（如APA格式）

### 生动比喻
> LLM做文本转换就像一个**精通百国语言的翻译官**，同时还兼任**排版师、校对员和文体改写专家**——以前需要一整个团队干的活，现在几行提示词搞定。

## 第7课：Expanding（文本扩展）

### 核心概念
- 从简短输入（指令/话题列表）生成长文本（邮件/文章）
- 用途：头脑风暴伙伴、自动生成个性化回复

### Temperature参数
- **Temperature = 0**：输出确定性最高，每次结果一致，适合需要可预测输出的场景
- **Temperature = 0.7**：增加随机性和创造性，每次输出不同
- 本质：控制模型在选择下一个token时的概率分布"锐利程度"

### 实战案例：自动回复客户评论
- 输入：客户评论 + 情感标签
- 输出：个性化回复邮件
- 重要：让邮件表明自己是AI生成的（透明性）

### 生动比喻
> Temperature就像**调节音乐播放器的"随机播放"强度**——设为0就是严格按顺序播放（可预测），设为0.7就是半随机（有惊喜），设为1就是完全随机（可能跳到意想不到的歌）。

---

## 第8课：Chatbot（聊天机器人）

### Chat Completions格式
- **System Message**：设定助手的行为和角色（用户看不到）
- **User Message**：用户的输入
- **Assistant Message**：模型的输出

### 关键概念：上下文（Context）
- 每次对话是独立交互，模型没有记忆
- 必须将之前的对话历史作为输入传递
- 上下文随对话不断增长

### 实战案例：OrderBot（披萨订餐机器人）
- System Message定义角色、工作流程和菜单
- 自动收集订单信息
- 最终生成JSON订单摘要

### 生动比喻
> System Message就像**导演给演员的角色说明书**——观众（用户）看不到，但它决定了演员（模型）如何表演。而Context就像**演员的台词本**——每次演出都要从第一页开始念，不带上之前的对话就会"忘词"。

## 第9课：Conclusion（结语）

### 课程总结
- 两大原则：清晰具体 + 给模型思考时间
- 迭代开发流程
- 四大应用能力：Summarizing, Inferring, Transforming, Expanding
- 自定义聊天机器人
- 鼓励动手实践，从小项目做起
- 负责任地使用AI
